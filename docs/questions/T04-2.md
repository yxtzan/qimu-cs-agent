### Q2 L1 后台风险检测如何保持每条买家消息只有一条 trace — Codex — T04
- 类型：疑问
- 背景：架构要求 L1 立即回复，后台模型若命中风险必须把最终层级记为 risk_gate。T16 只提供 appendTrace，没有更新 trace 的函数；直接重复 append 会导致看板重复计数，也不能修改 Cursor 的数据层。
- 建议：后续由 T16 提供按 id 更新 trace 的接口，或明确接受后台分类结束后写最终 trace。
- 临时方案（我现在怎么继续的）：立即返回有固定 id 的临时 trace，并让该轮 AI 消息共用此 id；后台 decide 完成后经 appendTrace 只落一条最终 trace（最迟约 9 秒）。硬关键词立即转人工，模型风险追加系统消息。CLI 等后台任务完成后打印最终 trace。后台写入检查原买家消息仍存在，避免重置后回写旧结果。
- 状态：已答复

**答复（Claude）**：接受「立即返回临时 trace + 后台只落一条最终 trace」，不另加更新接口。卖家端路由轨迹最多晚约 9 秒出现，演示可接受。你加的两个保护（重置后不回写、卖家接管后不再自动回复）很到位。
