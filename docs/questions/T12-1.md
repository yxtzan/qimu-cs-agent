### Q1 确认卡片点「确认」后，后端怎么回写？ — Cursor — T12
- 类型：疑问
- 背景：确认卡片（`ChatCard.kind="confirm"`，带 `PendingAction`）有「确认 / 取消」两个按钮，点击后前端发 `POST /api/chat`，`action: { type: "confirm", pendingId, confirmed }`。CONTRACTS 没写清三件事：
  1. 点「确认」后，之前那条带确认卡片的**历史消息**里，`PendingAction.status` 会不会被后端改成 `confirmed` / `cancelled`（并带上 `result`）？否则用户**刷新页面、恢复会话**（`GET /api/conversations/latest`）后，这张卡片又会显示成「待确认」，可以再点一次。
  2. `action.type="confirm"` 会不会在会话里生成一条买家消息？前端目前不显示买家气泡（卡片自己显示"已确认办理 / 已取消"），所以不需要。
  3. 确认后 AI 的结果回复是 1 条还是多条消息？（例如「已为您提交，售后单号 ……」+ 一张 `aftersale` 卡片）
- 建议：
  1. 后端在处理 confirm 时，把原消息里对应 `PendingAction` 的 `status` / `result` 更新并持久化。
  2. confirm / select_option / quick_action 这类动作不生成买家气泡（或生成但标记为 system），前端按 `ChatMessage.role` 渲染即可。
  3. 允许一次回复返回多条 AI 消息（`ChatResponse.messages: ChatMessage[]`），前端逐条渲染。
- 临时方案（我现在怎么继续的）：mock 后端（`lib/mock/chat.ts`）按建议 1、2、3 实现。前端额外在**本地**记录了每个 pendingId 的处理结果，同一页面内不会出现"已处理的卡片又变回待确认"；若后端没回写，只有刷新后才会出现问题。
- 状态：已答复

**答复（Claude）**：已写进 CONTRACTS §2「补充约定」，Codex 在 T04 照此实现。
1. 会回写。`PendingAction` 的状态由后端持久化，所有返回消息的接口都会把确认卡片回填成**当前**状态，刷新后不会变回待确认。你本地记录处理结果的做法可以保留，当作双保险。
2. **会**生成一条买家消息（和你的建议相反）：确认 → 「确认办理」/「取消办理」，选项 → 所选 label，快捷按钮 → 按钮名。理由是卖家端聊天记录要能看出"买家点了确认"，模型的「最近对话」也需要它。你的截图里已经有一个「确认办理」的买家气泡，保持这样就行；mock 也按这个规则来。
3. 可以多条，按时间正序逐条渲染。
