# 栖木客服 Agent 演示剧本（T20）

> 维护者：Claude。人类演示时照着用。时长：主线 5–6 分钟，加演 2–3 分钟。
> 更深的追问（数据怎么编、风险闸门、幻觉、意图模糊）看讲解手册「深入几个关键问题」一节。

---

## 0. 演示前 30 分钟：检查清单

在「客服 agent」文件夹的终端里，依次做：

1. 拉最新代码：`git checkout main && git pull`（报 SSL 错误就隔几秒重跑）
2. 装依赖：`npm install`
3. 打开 `.env.local` 核对（**只看，不要发给任何人**）：
   - 有 `OPENROUTER_API_KEY=` 且后面有值
   - `NEXT_PUBLIC_USE_MOCK=0`
   - `AGENT_MODEL=qwen/qwen3.7-flash`、`AGENT_REASONING=off`
   - `JEV_KEEPALIVE_MS=120000`
4. 启动：`npm run dev`，浏览器打开 http://localhost:3000
5. 右下角书本按钮 → 演示指南 → 底部「重置演示数据」→「确认重置」（页面会自己刷新）
6. **预热**：随便开聊天窗发两次「你好」，第二次应在 1 秒内回复。Jev 冷启动要几秒，别让观众看到第一次的等待。
7. 准备第二个浏览器窗口给卖家端：打开 http://localhost:3000/seller ，按 `Cmd+Option+I` 打开开发者工具 → 左上角手机图标 → 选 iPhone 或宽度 390。
8. 买家端窗口里，聊天窗右上角「调试」开关**打开**——第 3、4 步要用它讲路由。

演示途中玩乱了：演示指南底部「重置演示数据」，10 秒回到初始状态。

---

## 1. 开场（30 秒）

> 「这是一个女装店的智能客服 Demo，店和数据都是虚构的。它的核心是一个**三层漏斗**：固定说法用规则秒回，大部分问题用一个很便宜的判断模型 Jev 分流，只有复杂的多步问题才交给大模型；另外有一道**风险闸门**，所有消息都会过一遍，投诉、过敏、诈骗这类直接转人工。我从买家的一次完整购物经历走一遍，最后看卖家后台和成本。」

---

## 2. 主线六步

每一步都从演示指南点「开始」：它会切好买家、打开页面、**新开一段对话**、填好话术，你只需要点「发送」。

### 第 1 步 · 售前：问尺码和洗护（买家：林小满）

- **操作**：第 1 步「开始」→ 发送「我 160cm 50kg 穿什么码？这件能机洗吗」
- **会等多久**：5–15 秒（要查知识库再生成回答）。等的时候说台词。
- **台词**：
  > 「一句话里两个问题。尺码不是让模型猜的，是按尺码表**算**出来的——160、50 公斤落在 M 码。洗护是从店铺知识库里检索出来再回答，下面『参考了几条资料』可以点开看依据。模型不许编资料里没有的东西。」
- **观众看到**：尺码卡「推荐 M 码」+ 洗护说明 +「参考了 N 条资料」

### 第 2 步 · 售中：查物流

- **操作**：第 2 步「开始」→ 发送「到哪了」
- **会等多久**：1–2 秒
- **台词**：
  > 「只说了三个字，系统没有追问是哪个订单——因为买家是从订单页点进来的，订单号已经带上了。这种高频、说法固定的问题走第一层规则，几乎不花钱。」
- **观众看到**：物流时间线卡片

### 第 3 步 · 售后多步：换码 + 问优惠券（重头戏）

- **操作**：第 3 步「开始」→ 发送「上周买的那件外套换成 L，顺便看看有没有券」→ 等确认卡出现 → 点「确认」
- **会等多久**：5–20 秒。等的时候指着调试面板讲。
- **台词**：
  > 「这句话有两个诉求，还要先找到『上周那件外套』是哪一单，第二层接不住，交给大模型。它会一步步调工具：查订单、查 L 码库存、生成换货申请、查优惠券。注意，它**不能直接改订单**——只能生成一张确认卡，买家点了确认才真正办理。」
  > （点确认后）「售后单号出来了，左边订单页也同步出现了售后信息。过期的优惠券不会出现在这里。」
- **观众看到**：换货确认卡 → 确认后售后单 `AS20261005001` + 两张可用券；左侧订单页出现售后
- **如果它转人工了**：别慌，这是设计好的兜底——「大模型拿不准或超时，就交给人工，不硬答」。演示指南底部重置，再走一次。

### 第 4 步 · 高风险：过敏 + 投诉（买家：周雨桐）

- **操作**：第 4 步「开始」→ 发送「衣服穿了全身起红疹，你们不处理我就去 12315 投诉」
- **会等多久**：1–3 秒
- **台词**：
  > 「这条触发了风险闸门：健康问题加投诉威胁。AI 不去安抚、不去解释政策，直接转人工，顶栏变成『等待人工接入』。闸门有两道网——关键词一定能抓住『12315』这种明确说法；Jev 能抓住换了说法的，比如『脖子痒得睡不着』『我要发到网上让大家评评理』。」
- **观众看到**：「等待人工接入」+ 系统消息；调试面板里风险分数

### 第 5 步 · 卖家端：接管

- **操作**：切到卖家端窗口（手机宽度）→ 会话列表顶部红点会话 → 点进去 → 看「AI 上下文」里的转人工原因和一句话摘要 → 接管 → 回复一句（例如「您好，我是阿栖，非常抱歉，马上为您处理退货退款」）→ 切回买家端
- **台词**：
  > 「卖家端是手机优先的，可以加到主屏幕当 App 用。转人工的会话排最前面，AI 已经写好一句话摘要，客服不用翻聊天记录。接管、回复——」（切回买家端）「——买家这边几秒内就收到了。」

### 第 6 步 · 看板收尾

- **操作**：卖家端底部「看板」→ 点「近 7 天」
- **台词**（数字以屏幕为准，下面是重置后的典型值）：
  > 「近 7 天 295 条消息，78% 在前两层就解决了，加上大模型自动解决的，合计 90% 不用人工。L3 只处理 12% 的消息，但它单条成本是第二层的 3 倍多，平均要等 5.8 秒，第二层只要不到半秒。所以要尽量把消息挡在前面，又快又省。」
  > 「下面的评测成绩是 60 条测试对话的真实跑分：57 条通过，风险召回 100%，误报 0。另外我们留了 15 条系统从没见过的题，过了 13 条——这个更能说明它对新问题的处理能力。」
- **注意**：「近 7 天」里的历史消息是模拟流量（看板底部有小字注明），今天新发的是真实消息。被问到就直说。

## 3. 加演（时间够再做，各 30–60 秒）

**A. 情绪升级：连续两轮不满就转人工**（买家端随便一个买家，新开对话）
1. 发「什么破快递，三天了还没动」→ 先有一句安抚，回复下面多一个「转人工」按钮（黄色区间）
2. 再发「到现在还没动静，真是太慢了」→ 自动转人工，原因「连续两轮情绪或风险偏高」
> 「不是一句话就定生死。拿不准时先安抚、把转人工的按钮递给买家；连续两轮都不满，就主动转。」
（情绪分数有波动，偶尔第一句没进黄区，换一句更冲的说法即可。）

**B. 误报陷阱：提到律师不等于要投诉**
- 发「我老公是做律师的，他说你家大衣版型挺正」→ 正常回答，不转人工
> 「早期版本这句会被『律师』两个字误判。我们没有加例外词表，而是改了问 Jev 的方式：问『买家本人是否在威胁』，而不是『是否提到律师』。」

**C. 规则要做减法**
1. 买家端发「尺码不合适想退货」→ 被一条过宽的规则当成「问尺码」（调试面板显示 L1 / R007）
2. 卖家端「规则」页 → R007 带橙色「建议删除」（误判率高）→ 关掉
3. 回买家端新开对话再发同一句 → 正确识别为退货
> 「规则越多越容易误吞。看板和规则页会根据命中和误判数据，提示哪条该删。」
（做完记得把 R007 打开或重置，免得影响下次演示。）

## 4. 今天走查要额外核对的两处（T09b-1，Claude 改了提示词但没有真实模型复验）

1. 演示指南切到买家「陈思」（或顶栏切换买家 B003）→ 打开订单 QM2026100402（待付款）→ 聊天发「付不了款怎么办」
   - ✅ 应该：说明订单是待付款状态，原因目前无法确认，可以请你补充看到的错误提示
   - ❌ 不应该：猜「银行卡余额不足」「网络问题」「换支付方式」这类工具没给的原因
2. 打开订单 QM2026100401（已付款）→ 发「这单什么时候发货」
   - ✅ 应该：说明已付款未发货，回答发货时间（L2 会给出预计时间）或说目前无法确认
   - ❌ 不应该：让你「补充错误提示」

## 5. 常见追问（一句话版）

| 被问到 | 回答要点 |
|---|---|
| 数据是真的吗？ | 全部虚构，但按一份规格书生成、有独立脚本校验，同一条规则在商品、订单、知识库里处处一致。 |
| Jev 是什么，为什么不全用大模型？ | Jev 是只做判断、不写字的模型：一次请求同时答意图、多诉求、4 项风险和情绪，热状态约 0.4 秒、每次约 ¥0.0004。大模型做同样的分类要 2–3 秒。 |
| 模型会不会胡说？ | 事实类回答（物流、订单、退款、尺码）都来自工具或计算，不让模型写；咨询类只许按知识库回答并标来源，查不到就说不确定；改订单必须买家确认。**运行时还没有自动检测幻觉**，这是已知短板。 |
| 意图拿不准怎么办？ | 置信度低于 0.7 交给大模型；不知道指哪个订单就弹选项让买家点；连续两轮没解决转人工。「五五开要不要转人工」目前是黄标 + 递转人工按钮，还没做更细的反问。 |
| 评测分数靠谱吗？ | 60 条主评测 57/60；但提示词有一部分是对着主评测的失败补出来的，所以另留了 15 条没见过的题，13/15。对外以 13/15 说明泛化能力。 |
| 成本？ | 第二层每千条约 ¥0.4，大模型层每千条约 ¥1.4（模拟数据按实测口径）。真正的差距在速度：5.8 秒对 0.45 秒。 |
| 为什么不用 Dify / Coze？ | 需要并行调用、三级降级、毫秒级超时和自己的卖家后台，写在代码里更好控制；代码是 AI 写的，拖拽工具也不会更快。代价是非技术同学没法直接改流程图。 |
| 还有哪些没做好？ | 运行时幻觉检测；「五五开」的反问；大模型层的通用多步问题仍偶尔转人工（留出集 H13）；看板历史数据是模拟的。 |

## 6. 翻车预案

| 情况 | 怎么办 |
|---|---|
| 某一步等了 20 秒还没回 | 继续讲这一步的设计；30 秒还没回就说「这是外部模型偶发延迟，系统超时后会自动转人工」，然后重置再来 |
| 第 3 步直接转人工了 | 讲「拿不准就转人工」的兜底设计 → 演示指南重置 → 再走一次（通常第二次正常） |
| 页面报错或空白 | 刷新页面；还不行就在终端 `Ctrl+C` 停掉，`npm run dev` 重启 |
| 卖家端没有红点会话 | 确认第 4 步发出去且顶栏是「等待人工接入」；卖家端下拉刷新 |
| 数据被玩乱了 | 演示指南底部「重置演示数据」 |
