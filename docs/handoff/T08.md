- 改了什么（逐条对应任务卡）：
  1. `qualityIssue`：按订单状态判断——已签收且在 7 天内（用 `DEMO_NOW`，含第 7 天）→ 方案 + 三个快捷回复；超 7 天且金额 > ¥500 → 转人工（原行为）；其他维持原样。

  3. `risk.ts`：情绪黄标门槛 1.5（0–3 分制），其余四项 0.5；导出 `yellowKeys()`、`hasKeywordHit()`。
  4. 关键词命中后等本轮 `decide()`：`decideProvider` 是 jev / llm 且该项模型分 < 0.3 → 降为黄标；其余（≥0.3、decide 失败、mock）照旧转人工。L1 只有关键词命中时才等。风险闸门的 trace 现在直接带 `decideProvider` / 概率 / 成本（不再靠后台补写）。
  5. 新文件 `lib/brain/caution.ts`：固定模板安抚语（不调模型，按 health > fraud > legal > abuse > emotion 选），并确保有「转人工」快捷回复；L1 不处理；pipeline 只加一行 `applyCaution(...)` 调用。
  6. 连续两轮黄标 → `applyCaution` 返回 `handoffReason`，由 pipeline 现有流程走 `handoffMessages / enterHandoff`（T05 之后的同一入口）；上一轮黄标从上一条买家消息的 trace.riskScores 用同一套门槛算。
  7. `withDecision` 写入 `trace.multiStep`。
  8. `warmup.ts` 导出 `warmJevNow()`；`JEV_KEEPALIVE_MS` 默认 120000（代码 + `.env.example`）。`JEV_KEEPALIVE_MS=0` 时重置预热也关闭（离线脚本用）。
