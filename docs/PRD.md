# PRD — 栖木客服 Agent

> 维护者：Claude（总指挥）。Agent 不得修改，有疑问写到 `docs/questions/`。
> 优先级：**P0** = 演示必须有；**P1** = 有时间就做；**P2** = 不做，只写进"后续规划"。

## 1. 一句话

一个电商通用智能客服 Agent：用三层漏斗（规则 → 轻量分类 → 大模型）以最低成本理解买家意图，用 RAG + 工具调用自动办事，遇到高风险或搞不定的情况无缝转人工；卖家能在手机上看到每条消息"是谁、花多少钱、多快"处理掉的。

## 2. 演示要讲的故事（所有设计服务于这三点）

1. **能办事，不只是能聊**：查物流、退款、换码都是真的调工具改数据，写操作会让买家确认。
2. **省钱又快**：大部分消息在规则层 / 上下文层就被处理掉，只有少数复杂请求才用到大模型。路由看板上能看到各层占比、延迟和成本。
3. **知道自己什么时候不该接**：高风险（投诉威胁、过敏受伤、盗号诈骗、情绪激烈）秒转人工，人工接手时能看到完整上下文，买家不用重复说明。

## 3. 用户

| 用户 | 场景 |
|---|---|
| 买家「小林」 | 逛店、问尺码、下单后查物流、收到货想换码 / 退款 |
| 店主 / 客服「阿栖」 | 在手机上接管转人工的会话、导入知识库、看 AI 表现、调规则 |

## 4. 买家端（桌面 Web，`/`）

### 4.1 页面

| 路由 | 页面 | 优先级 | 要点 |
|---|---|---|---|
| `/` | 商城首页 | P0 | 店铺头图 + 分类标签 + 商品网格（图、名、价、销量） |
| `/product/[id]` | 商品详情 | P0 | 图、价格、颜色 / 尺码选择、库存、材质洗护、尺码表；「问客服」按钮（带 `productId` 打开聊天） |
| `/orders` | 我的订单 | P0 | 按状态分 Tab；每个订单卡片有「联系客服」按钮（带 `orderId` 打开聊天） |
| `/orders/[id]` | 订单详情 | P0 | 商品、金额、收货信息、物流时间线、售后状态 |
| 全局 | 客服聊天窗 | P0 | 右下角悬浮按钮，展开为侧边抽屉（宽 420px） |
| 顶栏 | 买家切换器 | P0 | 下拉切换当前演示买家（不同买家有不同订单），演示用 |

商品图片：用 `https://picsum.photos/seed/<productId>/600/800` 这类占位图，或纯色块 + 商品名首字。不要用真实品牌图。

### 4.2 客服聊天窗（核心）

- **快捷按钮**（L1 入口）：`查物流` `退款进度` `尺码推荐` `转人工`。
- **上下文条**：从订单页 / 商品页进入时，输入框上方显示"正在咨询：订单 QM2026…"或商品缩略卡，可关闭。
- **消息类型渲染**（见 CONTRACTS 中的 `ChatMessage.card`）：
  - 纯文本
  - 订单卡片、物流时间线卡片、商品卡片（可点击跳转）
  - **确认卡片**：「确认为订单 xxx 申请退款 ¥199？」+ 确认 / 取消按钮（D006）
  - 选项卡片：多个订单时让买家选是哪一单
  - 系统提示：「已为您转接人工客服，阿栖正在赶来」
- **人工模式**：转人工后，顶部显示"人工客服 阿栖 为您服务"，买家端每 2 秒轮询新消息。
- **调试开关**（P0，演示利器）：聊天窗右上角一个 🔍 开关，打开后每条 AI 回复下方显示一行小字：`L2 上下文层 · 意图 refund_progress · 置信度 0.91 · 186ms · ¥0.00002`。

## 5. 卖家端（移动端优先 Web + PWA，`/seller`）

底部 Tab 导航：**会话 / 看板 / 知识库 / 规则**。

| 路由 | 页面 | 优先级 | 要点 |
|---|---|---|---|
| `/seller` | 会话列表 | P0 | 分组：待人工（红点，按等待时长排序）/ AI 处理中 / 已结束。每条显示买家、最后一句、风险标签、所在层 |
| `/seller/c/[id]` | 会话详情 / 人工接管台 | P0 | 消息流 + 顶部「接管」/「交还 AI」按钮 + 输入框；可展开「AI 上下文」面板：DialogState（当前任务、已填槽位、历史动作）、每条消息的路由轨迹、转人工原因 |
| `/seller/dashboard` | 路由看板 | P0 | 见 5.1 |
| `/seller/kb` | 知识库 | P0 | 文档列表（标题、分块数、导入时间）；**导入**：上传 .md/.txt 或粘贴文本；导入后可在页面上直接"试搜一下"看命中的分块 |
| `/seller/rules` | 规则管理 | P0 | 规则列表：关键词/正则 → 意图，开关，**命中次数、误判次数、最后命中时间**；「建议删除」标记（命中率低或误判高）——体现"规则层做减法" |
| `/seller/assistant` | 店铺 AI 助手 | P1 | 卖家用自然语言做分析：「上周退款最多的 3 个商品，按原因分类导出」→ 多步工具调用 + 可下载 CSV |

### 5.1 路由看板（演示的高光页面）

时间范围：今天 / 近 7 天。指标：

- 顶部 4 个数字：总消息数、自动解决率、转人工率、平均响应时间
- **漏斗图**：风险闸门拦截 → L1 规则 → L2 上下文 → L3 大模型 → 人工，各层消息数与占比
- 每层的平均延迟、每千条消息的成本（¥）
- 意图分布（售前 / 售中 / 售后 / 其他 四大类 + 明细）
- 低置信度样本列表（confidence < 阈值的消息，可点击查看）——"这些是模型拿不准的，需要人看"
- 评测成绩卡：最近一次 `npm run eval` 的意图准确率、路由准确率、风险召回率

看板数据来源 = 历史种子会话（虚构，约 300 条消息的路由日志）+ 实时演示产生的新日志，所以打开就有数据。

### 5.2 PWA

`manifest.webmanifest`（名称「栖木商家」、主题色、图标），iOS 的 `apple-touch-icon`。不需要离线功能。

## 6. 非功能

- AI 回复首字（整条回复）在 L1/L2 内 < 1.5s，L3 < 8s；超时给兜底话术。
- 没有 API key 时 `mock` 模式可完整演示（回复质量差一些，但流程全通）。
- 所有金额显示 `¥` 两位小数；时间显示为相对时间（"3 分钟前"）+ 悬停显示绝对时间。

## 7. 视觉规范

- 气质：干净、温和、有一点高级感的女装店，不要淘宝式的大红大促。
- 主色：墨绿 `#2F4F3E`；辅助：米白 `#F7F4EE`、暖灰 `#8A8378`；风险色：`#C2410C`；成功色：`#15803D`。
- 字体：系统字体栈（`-apple-system, "PingFang SC", "Microsoft YaHei", sans-serif`）。
- 圆角 12px，卡片轻阴影，留白充足。
- 层级标签配色（看板和调试信息统一使用）：风险闸门=橙、L1=灰蓝、L2=墨绿、L3=紫、人工=红。

## 8. 演示剧本（5 分钟，Claude 会在 T20 写成详细台词）

1. **售前**（买家端商品页）：「我 160cm 50kg 穿什么码？这件能机洗吗」→ L2 识别尺码 + 洗护 → RAG 回答，引用尺码表。
2. **售中**（订单页点联系客服）：「到哪了」→ 槽位已预填订单 → L1/L2 直接查物流，显示时间线卡片。
3. **售后多步**：「上周买的那件外套换成 L，顺便看看有没有券」→ L3 大模型：查订单 → 查 L 码库存 → 生成换货确认卡 → 查优惠券。买家点确认 → 订单状态真的变了。
4. **高风险**：「衣服穿了全身起红疹，你们不处理我就去 12315 投诉」→ 风险闸门命中（健康 + 投诉威胁）→ 秒转人工。
5. **切到手机卖家端**：红点会话 → 打开看到 AI 上下文和转人工原因 → 接管回复 → 买家端实时收到。
6. **看板收尾**：「今天 300 条消息，83% 自动解决，L3 只用了 12%，每千条成本 ¥0.8」。
