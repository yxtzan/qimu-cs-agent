## 4. 尺码表（`size_chart.json`）

| 尺码 | 身高 cm | 体重 kg | 胸围 cm | 腰围 cm |
|---|---|---|---|---|
| XS | 150–154 | 40–44 | 80 | 62 |
| S | 155–159 | 45–49 | 84 | 66 |
| M | 160–164 | 50–54 | 88 | 70 |
| L | 165–169 | 55–61 | 92 | 74 |
| XL | 170–175 | 62–70 | 96 | 78 |

推荐算法（`recommend_size`，确定性）：
1. 分别按身高、体重查尺码，取**较大**的那个。
2. 版型修正：`宽松` 且身高、体重都落在该码区间的下半段 → 可小一码，并在说明里写「喜欢宽松效果可选 X，想合身选 Y」；`修身` 且任一指标落在区间上沿（最后 1cm / 1kg）→ 大一码。
3. 超出表格范围 → 不推荐，建议转人工。
4. 例：160cm / 50kg → M。

## 6. 业务规则（工具层必须校验，知识库必须一致）

| 规则 | 内容 |
|---|---|
| 7 天无理由 | 签收后 7 天内（含第 7 天），吊牌完好、未洗涤，可无理由退货或换货 |
| 退货运费 | 非质量问题由买家承担；**金卡会员免退货运费**；质量问题由商家承担 |
| 质量问题 | 签收后 15 天内可申请，需提供照片；金额 > ¥500 的质量问题转人工审核 |
| 换货 | 同款换码 / 换色，每单每件限 1 次，目标 SKU 必须有库存；换货新件在收到退回件后 24 小时内发出 |
| 退款到账 | 商家确认收到退货后 24 小时内发起退款，原路退回 1–3 个工作日 |
| 仅退款 | 未发货订单申请即退；已发货需先拒收或退回 |
| 取消订单 | 仅 `pending_payment` / `paid` 可取消；`paid` 取消后自动全额退款 |
| 改地址 | 仅 `paid`（未发货）可改 |
| 发票 | 电子普通发票，确认收货后在订单详情申请，1 个工作日内开具 |

## 8. 普通生成数据要求

- 商品：名称像真实女装店（「xx 感 xx 裙」风格，不用任何真实品牌名），每个商品 2–3 色 × 4–5 码，约 10% 的 SKU 库存为 0（部分有补货日期）。
- 订单：分布在 DEMO_NOW 前 60 天；状态比例大致 completed 45% / delivered 15% / shipped 12% / paid 8% / pending_payment 5% / cancelled 15%。每单 1–3 件。
- 物流：shipped 及之后的订单都有 `logistics`，节点时间合理递增，城市路线合理。约 3% 物流异常（`exception`）。
- 售后：约 30 条，`reason` 用**口语化中文自由文本**，同一类原因要有不同说法（「腰太紧了」「M 码偏小」「比想象中短」「颜色和图片差好多」「洗了一次就起球」「不喜欢了」…），`reasonCategory` 留空——留给 P1 的「店铺 AI 助手」用 Jev 批量打标签演示。
- 手机号、地址全部虚构；手机号统一使用 `138****xxxx` 显示格式。
